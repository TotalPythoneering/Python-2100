## Lessons

100: Welcome to Python 2100

In Python 2100 we'll be taking a closer look at object factories,
frameworks, and enhanced class-creation strategies.

200: Basic Inheritance

Because there is much more to Object Orientation than using the
\`class\` keyword, we'll start with a basic keyword, class, and concept
review.

300: Relationship Checking

Understanding the 'genetics' behind classes & instance relations, we'll
review how to discover the relationships between our objects - as well
as classes - in Modern Python.

400: Frameworks Packages

From built-in functions to instances of our own classes everything is an
object is Python. Yet member operations need not return anything useful.

500: D.I.Y Abstract

How to avoid exceptions by creating abstract / reusable base class
'signatures' in classic Python?

600: Multi-Creations

There can be one - and only one - \_\_init\_\_ defined for any Python
class. Yet we've other ways to create objects!

700: Getters & Setters

Getters & setters can help encapsulate function calls - so too might
other member operations manage other initialization paradigms.

800: Keyword Args

Review how complex arguments not only help extend our \_init\_\_ ops,
but how \*args and \*\*kwargs are supported by Modern Python.

900: A Factory Pattern

Using a 'recipe' (class maker) with a properly-named 'non-instanced
class member' can support alternate class creations.

1000: Class Methods

Unlike 'self' creating 'factory orders' for use by other objects,
passing around creation 'recipes' need not be the object to be created.

1100: Multiple Inits

We now know enough to name more than any single way to create our
objects.

1200: Factory Practice

Relying upon the idea that our abstracts always return \`None,\` let's
challenge ourselves to create a safer factory pattern?

1300: Attribute Detection

Object have 'slots' - and slots have names - that's those are the only
concepts we'll need to understand orders, classes, instances, as well as
ALL framework 'ops.

1400: Pattern Detection

As we saw in Python 2000 providing robust testing can be not only fun,
but unearthing all assumptions is why 'safe coding is no accident?' 🫤
